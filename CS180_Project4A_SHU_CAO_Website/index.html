PROJECT OVERVIEW

One scene. Multiple perspectives.
One coherent view.

This project implements the building blocks of panorama stitching without high-level homography or warping APIs: correspondence selection, least-squares homography estimation, inverse image warping, hand-coded interpolation, and mask-weighted compositing. As a bonus, I explore cylindrical projection and compare it with planar results.

A.1 — SHOOT AND DIGITIZE PICTURES

Three scenes, six views.

I use three image pairs with overlapping views: an outdoor stone square, a wood-paneled reading room, and a gallery. Distinctive architectural details provide correspondence landmarks. The overlap supports registration, while changes in viewpoint also reveal the limitations of a single projective transform in a three-dimensional scene.

A.2 — RECOVER HOMOGRAPHIES

Geometry in every pixel.

I initially selected 12 point correspondences per scene using a manual click interface that labels and connects matching locations. For the final panoramas I used a separate refined set of 16 points per scene. Both stages are documented here so the diagnostic figures are not mistaken for the final matrices.

PROJECTIVE RELATION

3 × 3 homography

Homogeneous points are related up to a nonzero scale. I fix h33 = 1 to obtain eight unknowns.

[x′, y′, 1]T ∼ H [x, y, 1]T

H = ⎡ h₁₁   h₁₂   h₁₃ ⎤
    ⎢ h₂₁   h₂₂   h₂₃ ⎥
    ⎣ h₃₁   h₃₂    1   ⎦
01

Cross-multiply

u = (h₁₁x + h₁₂y + h₁₃)/(h₃₁x + h₃₂y + 1)
v = (h₂₁x + h₂₂y + h₂₃)/(h₃₁x + h₃₂y + 1)

02

Build the linear system

For each (x, y) → (u, v):

[x y 1 0 0 0 −ux −uy] · h = u
[0 0 0 x y 1 −vx −vy] · h = v
03

Least-squares solution

Stack the two equations per correspondence into A h = b. With 12 or 16 matches, this is overdetermined (24×8 or 32×8). I solve h* = argmin ‖Ah − b‖² with numpy.linalg.lstsq.

04

Normalize and validate

Before solving, center and scale point coordinates to mean distance √2, then denormalize H = Tright−1 Hnorm Tleft. Divide by H33 and measure reprojection error in pixels.

A.3 — WARP THE IMAGES

Turning perspective
into front-facing geometry.

For each rectification, I select the four corners of a known rectangular painting in clockwise order (top-left → top-right → bottom-right → bottom-left) and define a front-facing destination rectangle. The computed homography maps the quadrilateral to that rectangle.

INVERSE MAPPING

Sample rather than splat.

For every destination pixel p′, compute p = H−1p′ and sample the source image at the resulting continuous coordinates. This avoids holes caused by forward mapping.

p = H−1 p′

Ibilinear(x,y) = (1−a)(1−b)I₀₀
+ a(1−b)I₁₀ + (1−a)bI₀₁ + abI₁₁
01 / NEAREST NEIGHBOR

Fast, discrete sampling

Round each inverse-mapped location to the closest integer pixel. It is inexpensive but makes hard edges and aliasing more apparent.

02 / BILINEAR

Four weighted neighbors

Blend the four surrounding pixels using the fractional horizontal and vertical offsets. It smooths jagged edges at a modest computation cost.

A.4 — BLEND IMAGES INTO A MOSAIC

Stitch the views.
Hide the seams.

I keep the right-hand photograph as the reference and project the left-hand photograph onto its image plane. The output canvas is computed from the extrema of both original and transformed image corners; translation makes all canvas coordinates nonnegative. I use inverse bilinear warping and valid-pixel masks to compose the panorama.

01

Reproject corners

Find the warped extents of both views, then create a translation T for the positive-size output canvas.

02

Warp to one canvas

Use T H for the left image and T I for the right image, sampling source RGB by inverse bilinear interpolation.

03

Construct alpha masks

Track where each warped image has valid pixels. Use distance to each valid mask boundary as a smooth confidence weight.

04

Feather the overlap

In shared regions, take a weighted average of the two images instead of abruptly overwriting pixels.

Imosaic(p) = [wL(p)IL(p) + wR(p)IR(p)] / [wL(p) + wR(p)]

A.5 — BELLS & WHISTLES ★

A new surface
for a wider world.

I implemented cylindrical projection as an additional image representation. Both images are first resampled onto a cylinder using inverse mapping, the original selected points are transformed to cylindrical coordinates, and alignment plus feather blending are performed in the cylindrical domain. The outputs are then compared with planar mosaics.

CYLINDRICAL COORDINATES

Wrap the viewing plane.

With focal-length parameter f and image center (cx, cy), centered pixel coordinates (x, y) are mapped to cylinder coordinates. I use a nominal f around the image width; it is a visual parameter, not a camera-calibrated focal length.

xcyl = f · atan((x − cx)/f) + cx

ycyl = f(y − cy)/√((x − cx)²+f²) + cy
Interpretation. Cylindrical projection can reduce planar stretching over wider fields of view. It does not eliminate parallax, and with just two moderate-overlap images it is not guaranteed to look more natural than the planar version.

WHAT I LEARNED

Correspondences matter more than cosmetic blending.

The largest improvement came from selecting accurate, well-distributed point matches. Normalized least squares provided a stable projective model, inverse warping avoided missing samples, and bilinear interpolation improved visual continuity. Blending softened the seams, but geometry and scene depth still governed the quality of the results. Cylindrical mapping offered a useful alternative panorama geometry rather than a universal fix.
